# VibeHub 中文“AI 味儿”适配规则

本文件根据 VibeHub《防止 AI 味儿》中的“中文口癖”条目进行概括和竞赛文档化改写。重点不是禁词，而是避免一组容易形成模板感的默认表达。

## 1. 不使用安抚式客服腔

避免“稳稳接住你”“你已经抓住重点了”“你这个判断非常准确”等回应式话术进入正文。

竞赛材料应直接写事实、判断和依据。

## 2. 少用抽象单字动作

“收一下、提一层、落回去、压一压、顺一下、砍一刀、收口、落盘”等适合口头协作，不适合正式申报书和技术文档。

改为明确动作：删除、合并、补充证据、调整结构、统一术语、压缩篇幅、形成定稿。

## 3. 不给普通词滥加引号

不要为了强调而给“真实”“智能”“可信”“创新”等普通词加引号。只有以下情况使用引号：原话、特殊概念、术语首次界定、具有反讽或非通常含义。

## 4. 不用夸张比喻替代功能说明

避免把项目写成“灯塔、桥梁、钥匙、引擎、底座、护城河、神经中枢”等，除非这是行业中已有明确含义的术语且上下文确有必要。

优先说明模块输入、处理、输出和价值。

## 5. 不无依据提升立意

一个功能解决一个具体问题时，不要突然上升到“重塑行业未来”“重新连接人与人”“改变工作方式”。

竞赛材料中的社会意义必须由实际对象、场景、政策、调研、应用或结果支撑。

## 6. 避免“砍一刀/闭环/收口”式咨询黑话

“闭环”只有在确实描述闭环控制、反馈闭环、业务闭环或安全处置闭环时保留。其他场景改成真实流程关系。

例如：
- “形成研发闭环” → 写明“问题进入 issue，修复后重新测试，通过后合并”。
- “形成安全闭环” → 写明“告警进入研判，生成处置建议并回写结果”。

## 7. 不使用夸奖读者/作者的元话语

正文中不要出现“这个思路非常关键”“已经触及问题本质”。若确实需要评价一个方案，说明为什么：减少了哪一步、解决了什么限制、测试结果如何。

## 8. 克制“不是 X，而是 Y”

不要把普通功能包装成“不是一次升级，而是一场变革”。

如果需要做对比，直接列出旧方案和新方案的实质区别；没有对比信息时，只写新方案做了什么。

## 9. 删除“先说结论”的固定开场

“先说结论”“先把答案放前面”“下面用三点讲透”不是必要的正文。

摘要可以直接写结论；答辩稿可以自然开场，但不要使用固定主播式套话。

## 10. 不把所有内容拆成列表

两三句可以连续说明的内容不要强拆成三点。只有并列关系、步骤关系、参数清单、对比维度明显时使用列表。

竞赛材料要有段落，也要有表格/列表；不要让整页只有编号。

## 11. 不用“如果你愿意”式结尾

成稿直接结束在结论、下一步或实际内容上，不加“如果你愿意，我还可以继续……”之类聊天式尾巴。

## 组合检测

以下组合出现时，优先判定为“AI 味”较重：

- 大量抽象词 + 夸张比喻 + 价值升华；
- “不是 X，而是 Y” + 三项排比 + 段尾升华；
- 每段固定“首先/其次/最后” + 每点句式相同；
- 标题全部口号化 + 正文缺少数字、动作、对象；
- “赋能/闭环/生态/格局/底座”密集出现，但看不出系统到底做了什么。

## 竞赛文档改写准则

发现上述模式时，不要只做同义词替换。重新回答三个问题：

1. 这句话实际想传达的事实是什么？
2. 哪个技术动作、调研结果、测试结果或项目成果能支撑它？
3. 删掉修辞后，评委是否仍能理解它为什么重要？

如果答案不清楚，说明原句信息密度不足，应补事实而不是换词。

## 强制直述与引号规则

- 竞赛材料优先直接陈述事实、动作、原因、结果和判断。
- 禁止使用先否定后转折的强调模板，包括“不是 X，而是 Y”“不以 X，而是 Y”“并非 X，而是 Y”“不是为了 X，而是为了 Y”。
- 遇到此类句子时，删除前置否定项，直接保留真正需要表达的结论，并补充事实或证据。
- 正文、标题、题注、表格说明、PPT 文案和答辩稿原则上不使用中文双引号作强调。
- 文件、政策、标准、书籍名称使用书名号；产品、模块、技术术语直接书写，不套引号。
- 除引用规范要求的逐字引文外，引用内容优先改为转述，保持事实含义与来源不变。
